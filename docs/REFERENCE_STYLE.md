# 参考视频的视觉与动画规范

本记录来自用户提供的参考视频，仅用于改善本工具的创作方式。视频约 126.208 秒，画面 960×544，内容是生日悖论。检查了全片每十秒的接触图，以及 32–39 秒、47–54 秒、72–79 秒的逐秒静帧。未生成新视频，未把用户视频或抽帧放入公开网站资源。

## 核心判断

参考片的吸引力来自**画面参与推理**：一个新连线代表一个新的配对机会，一个新分式代表新增的一个人，一段新曲线代表概率的继续变化。黑金配色、衬线字体和漂浮粒子负责统一质感，不能替代这些实际知识变化。

现有页面里反复出现「三个圆点＋不同标签」的问题，不应只通过增加背景颜色或改写提示词来解决。每个镜头要生成独立的对象、空间布局和时间事件，允许跨镜延续同一对象，但必须让新的知识关系在画面上可见。

## 可复用的美术语言

| 层面 | 参考片观察 | 产品中的实现原则 |
| --- | --- | --- |
| 背景 | 近黑、带暖褐光晕，少量深浅不同的漂浮尘点 | 背景低对比，主图形与正文保持足够亮度；不要用密集网格覆盖全片 |
| 主色 | 暖金与象牙白；少量玫瑰灰区分另一组概率 | 一组主要强调色、一组辅助色；同一知识对象保持同色 |
| 字体 | 中文标题与字幕偏宋体，数字和分式偏古典衬线；边角英文稀疏字距 | 黑金叙事可用 Noto Serif CJK SC / Songti SC / Georgia；其它风格换真正的字体、线条与纹理语言，不只换色 |
| 层次 | 章节号很小，主标题集中，数值在关键时刻成为最大对象 | 主图形或关键数值优先；标签不抢主角，章节信息不占据大块空间 |
| 排版 | 开场居中问题；推演阶段标题靠左、图形展开；结论阶段左右比较 | 每镜独立构图，不固定「顶端大标题＋正中图形＋底部说明」一种布局 |
| 线与面 | 细线、微亮端点、很克制的填充，图表有完整坐标与刻度 | 线条必须有含义，线的生长与数据变化同步；不用无意义的装饰连线冒充关系 |
| 字幕 | 底部独立区域，主要是 1–2 行短句；与主图形之间留白 | 保留字幕安全区，手机竖屏要放大字号；不要照搬参考片较暗的小字 |
| 空间 | 大留白，前后层不同速度的尘点，柔和暗角 | 用明暗与少量视差提供深度，避免持续剧烈缩放或抖动 |

建议黑金近似色值（设计建议，非精确取色）：背景 `#0b0a07`，暖光 `#342a17`，正文 `#e5dfce`，主金 `#c7ac70`，辅助玫瑰灰 `#ae8277`。正文和字幕的可读性优先于复刻参考片的低亮度。

## 观察到的具体运动

1. **问题出现**：画面先给一个居中问题，细小粒子缓慢移动。此处的安静有阅读作用，不需要强行每秒制造新动作。
2. **对象入场**：人数或日期以小节点逐步出现，为后续推演建立同一批对象。
3. **比较的视角转换（约 32–39 秒）**：一开始是「我与其余人」和「任意两人」两个区域；左边逐渐退出，右边接管画面。右侧同一批节点逐批增加连线，最终成为完整配对网络。连接数量增长是真正的信息，而非背景装饰。
4. **公式与图表同步（约 47–54 秒）**：分式逐项增加，乘号和下一因子随后出现；下方曲线同时延长、增加样点和对应引导线。观众可以看到「新来一人」如何改变一个乘积。
5. **互补概率的重构（约 72–79 秒）**：先是一个居中数值与环线，随后整体移向左侧、分隔线出现，右侧引入另一组数值。前一状态保留为比较基准。
6. **大数值总结**：配对数量成为大字，原有网络缩小为旁证；结尾把人数、概率和配对数并排回扣，避免突然引入无关视觉元素。

这些段落含有适当停顿；「不似 PPT」不等于持续运动。应检查动作是否表达了对象关系、数量、过程或视角的变化。

## 逐镜画面生成的最小要求

每镜先描述以下内容，再生成绘图数据：

- **知识动作**：观众这一次要看见什么变化，例如「一条指令经过取指、译码、执行」；不能只写「解释 CPU」。
- **可见对象清单**：每个对象的具体外形、组成、数量、位置和角色。芯片应包含芯片轮廓、引脚、寄存器或指令路径，而不是圆点上贴「芯片」两字。
- **三段时间事件**：建立对象 → 发生变化 → 得到结果。说明每个事件改变哪个对象、属性或连线，何时发生，如何衔接。
- **构图与观看路径**：主角从哪开始，观众随后看哪里，主标题、标签、字幕分别放在哪。
- **下一镜衔接**：哪些对象保留、变形、移位或退出；保持颜色与语义一致。
- **事实依据**：数值、图表和公式来自什么前提；未知数据不能随意编造。

推荐返回的审查说明可以采用：

```json
{
  "visualIntent": "用指令包在芯片模块间的移动解释一次执行循环",
  "heroObjects": ["带引脚的芯片", "指令寄存器", "运算单元", "数据通路"],
  "beats": [
    {"at": 0, "meaning": "取指", "change": "一枚指令包进入寄存器"},
    {"at": 0.35, "meaning": "译码", "change": "指令分成操作码与地址，点亮对应通路"},
    {"at": 0.7, "meaning": "执行", "change": "运算单元接收数据并把结果写回"}
  ],
  "continuity": "结果沿同一条通路移出，成为下一镜的输入",
  "avoid": "不要把这四个对象画成四个只换标签的圆"
}
```

这段说明是设计约束，不要求照搬字段名。实际渲染数据需要包含足够的路径、形状、对象层和关键帧才能兑现说明；不能只保留自然语言动作而完全不渲染。

## 降低重复的质量检查

1. 比较画面结构时忽略标题、旁白和标签。若几何、位置和时间事件均相同，属于重复构图。
2. 连续镜头有相同主体可以是合理延续，但必须显式说明保留关系，并新增可见的推演，例如新增连线、公式因子、路径或曲线样点。
3. 每镜至少有一个**表达知识的变化**；只有淡入、漂浮粒子或标题缩放不算。
4. 全片至少使用几种与题材匹配的表达：实物结构、过程路径、数量累积、公式推导、数据图或对比。不能为了满足多样性而强行加入不相关图表。
5. 缩小到手机预览尺寸检查标题、标签和字幕。避免用极小的字和细线堆出「复杂感」。
6. 绘图请求失败或校验不通过时，保留该镜的失败状态并允许重试，不能悄悄退回圆点模板后宣称画面已经完成。

## 可直接放入画面设计提示词的短版

> 为当前镜头独立设计能解释知识的画面。先列出具体可见对象，再给出「建立—变化—结果」三个时间事件，每个事件必须改变真实图形关系、数量、路径或数据。构图要与前后镜头有区分；只有明确的连续推演可以复用对象。不要用相同几个圆点换标签，不要让所有镜头只有文字淡入。黑金风格采用暖金细线、象牙白衬线字、低对比暖光与少量尘点，图形和字幕优先保持清晰。数值、图表与公式必须符合已确认的事实，未知数据不要编造。字幕安全区留白；每个核心对象用清晰外形和组成让观众认得，而不只靠标签。

## 验证边界

本记录为视觉与逐帧差异分析，没有对音轨进行转写或听辨，不对具体配乐、乐器、节拍点作已验证结论。只抽帧验证了局部运动变化，不能声称已完成全片运动质量测量。公开产品应使用独立实现的画面与音乐，不分发用户提供的参考视频和抽帧。


## 2026-11-14：五支参考片与两支导出的对比

新增参考片约133–175秒，两支现有导出均约90秒。抽取各片不同阶段进行静帧对比，未转写音轨，也没有训练或微调模型。原视频、联系表及抽帧只用于本地观察，不进入公开源码。

参考片通过学习漏桶、聊天关系、概率道具、试卷分数和最优停止图形等不同主体讲因果。可借鉴的是同一物件延续、动作改变含义、局部特写与全景切换、关键结论留白。用户导出的问题集中在浅金字叠浅纸、过亮卡片洗掉轮廓、偶发整屏白场、几十个微型候选卡片及相近方框连线反复出现。

因此先建立视觉设定，再让每镜交代可辨认的主体、可见变化和观察结果；景别与材质服务解释，统一光源和道具比例，不机械复制参考镜头。代码运行器根据风格提供正确默认墨色和较低辉光，用实际帧测量持续低对比和背景失控。150秒预设提供更完整的叙事空间，节拍切换尊重讲解所需的停留时间，不能只把90秒内容放慢或堆更多文字页。
