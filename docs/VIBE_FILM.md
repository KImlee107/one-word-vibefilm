# vibe-knowledge-film 的实际接入

来源：https://github.com/HeyChengC/vibe-knowledge-film

固定提交：`62d51508aad00003dc6209afa80c4b5dc540de59`。实际分发上游 `engine/vk.js`，MIT 许可证随文件保留。仓库内 `.agents/skills/vibe-knowledge-film/SKILL.md` 是网站适配入口，`UPSTREAM_SKILL.md` 保存原流程。第三方参考片逐字稿和样片不在公开包中。

## 从换文字变成写动画

1. `/api/script` 按 skill 的“先形象、后文案”要求产生物件、动作、因果、连续性和时间事件。用户的完整导演说明也传入，生日模板带数学事实锚点。
2. `/api/scene-code` 为每镜重新编写 Canvas JavaScript 函数体，使用上游 `VK.Frame` 的路径、曲线、实心物件、层与文字接口。代码不是少数模板的参数填空。
3. 浏览器实际渲染18%、48%、78%静帧，并重复48%检查确定性。检查非空主体和前景变化；必要时自适应补采开头/结尾。运行器单独渲染不含文字的几何层，避免只改标签冒充机制运动。
4. 默认调用两次 `/api/review-scene`，每次把本镜三张实际 JPEG 与代码送给 所选的支持图片输入的视觉模型接口，让模型指出可见问题、修改完整代码，再重渲相同时刻。用户可减少到0或1轮；实际轮数、反馈、用量会记录在项目。没有 API Key 时不会进行这些调用。
5. 每镜完成后才进入完成计数。失败保留原因、失败代码和最后通过检查的代码草稿与原始不规范返回；补齐时继续剩余返修，避免重复调用已完成部分。明确要求重做时才丢弃草稿。代码和返修记录可在分镜编辑器查看。
6. 严格按镜头编号从前到后串行执行；可在时间线选择已有分镜的起止范围，不再优先复杂镜头。导出时每一帧使用相同代码和时间值渲染，合成配音、字幕、配乐或选定的真实 H3 镜头。

旧版 declarative composition 和内置示意为兼容已保存项目保留；新创作默认调用独立代码接口，不把示意模板冒充模型生成。

## 运行隔离

模型代码通过 Acorn 做语法、长度和环境访问检查。AST检查不是独立安全边界：代码只在 `sandbox="allow-scripts"`、没有同源权限的 iframe 内部的 Blob Worker 执行。其 CSP 禁止网络连接；父页面从不传 API Key、服务配置或存储内容，消息校验来源、随机通道与请求号。外层6秒 watchdog 可终止卡住的 Worker，主页面不执行动态代码。

上游引擎文件原样保留；运行桥接器把固定 W/H 改为当前画幅尺寸，以 OffscreenCanvas 适配其 `window/document` 需求。上游命令行 Playwright/ffmpeg 不作为网站服务依赖。最终浏览器编码继续使用 Mediabunny。

## 用户要求优先

上游原流程限制无旁白、16:9横屏。此网站按用户要求支持多比例、旁白、字幕及背景音乐；不要求用户阅读或批准内部每张分镜。用户上传配乐后才做本地节拍检测，检测可靠时把实际节拍时间给动画模型，不假造已分析参考配乐。

## 验证限度

已在 Node Canvas 中运行实际上游引擎及网页 Worker 桥接器，检查确定性、运动、不同主体与7种比例；接口测试模拟真实返回协议、三张视觉输入、失败和重复拒绝。开发时没有用户密钥，不调用付费模型、不制作成片。当前没有可用的共享浏览器控制工具，真实设备的 iframe/Worker、音画播放和最终编码仍需验证。代码检查和模型视觉返修不能保证每个题材都达到专业动画质量，仍可选镜头反复修改。

## 函数接口与错误修复

运行器通过外层词法作用域注入`ss/lerp/clamp/seg/smooth/E`等数学别名；`VK.*`同样支持，绘图代码可声明自己的同名变量。Acorn解析后检查未声明引用、嵌套函数、块作用域和解构声明。该检查不替代隔离环境。

过去提示词的短名称与仅有VK命名空间的运行器不一致，会造成`ss is not defined`。现有回归测试先在旧签名复现ReferenceError，再使用实际上游引擎和新Worker渲染同一代码，检验非空、运动及跳转确定性。

生成前用48×48本地探针检测引擎、字体、Worker及短名称，无模型调用。字体由Worker初始化加载；上游自动`seek(0)`在适配文档中禁用，由应用显式控制seek，避免错误在无人等待的异步回调中抛出。

`/api/scene-code/repair`接收保留的program、issue、phase及原分镜，只修复本镜代码。一次制作运行共享一个代码修复预算，独立于所选0/1/2轮视觉返修。二次失败按所选策略继续下一镜或暂停；鉴权、限流、网络、运行环境和服务配置错误始终暂停；用户可查看并下载代码诊断，再单独重试。浏览器环境、服务鉴权、网络、限流和取消不会触发代码修复调用。看图返修需选择真正支持图片输入的模型；纯文本模型可选择0轮并保留本地检查。

## 画面测量与排版

通过真实Canvas测字记录可见文本的字号、透明度、变换后字形包围盒；对持续多帧的过小、重叠、越界和密集文本给出问题报告。可见画面和去文字几何层分别计算指纹，跨时刻检查主体动作；公式和收束镜头允许文字本身推进。实际视觉轮次获得三张静帧、实际frameTimes和测量报告。仍有阻断问题时，不把画面计为完成。`fr.label`复用实际测宽并限制可读字号和两行，不含固定题材模板。

已有画面可通过「检查现有画面」在本地重新评估，检测不产生模型费用。Node回归使用同一上游引擎与Worker，并实际检查过竖屏示意向量的建立、相加和落定三个时刻；该内部回归图不作为网站模型生成结果。测量无法完全判断事实、审美、每条箭头的语义和每个题材的专业性，仍保留视觉返修和用户局部调整。
