# 音频接口与字幕方案

当前交付只包含网站及服务接口。尚未生成旁白、背景音乐或样片音频；用户在网站选择服务并主动点击生成后，才发起外部调用。

## 配音接口

本站提供 `POST /api/speech`。当前预设 MiniMax `speech-2.8-hd`，使用 `https://api.minimax.cn/v1/t2a_v2` 原生协议。用户只填写 MiniMax API Key，配音和视频共用这份页面内存中的密钥。浏览器将密钥随当次同源 HTTPS 请求发给本站，本站转发给 MiniMax，不保存密钥。

```json
{
  "config": {"provider":"minimax","baseURL":"https://api.minimax.cn","model":"speech-2.8-hd","apiKey":"仅当前请求使用"},
  "payload": {"text":"两枚公平的骰子，为什么七比十二更容易出现？","voice":"male-qn-qingse","speed":1}
}
```

适配器检查 MiniMax 的 HTTP 状态和 `base_resp.status_code`，将 `data.audio` 十六进制解码为真正的 `audio/mpeg` 二进制返回浏览器。默认中文青年男声 `male-qn-qingse`，格式为 MP3。连接测试仅查询系统音色列表，不合成音频。[官方同步语音文档](https://platform.minimax.cn/docs/api-reference/speech-t2a-http)。

未配置服务或服务不支持配音时，界面应说明“配音服务未配置”或“不支持此能力”，保留静音画面及音乐导出的选择。外部费用预估必须与实际计费分开显示。

## 分句字幕与对齐

当前按镜头分别生成配音，保留音轨与 sceneId 的映射；用户可只重做选中镜头或补齐缺失旁白。字幕按镜头时长分页，当前没有逐字对齐。以后若服务商提供词句时间戳，字幕数据可以统一为：

```json
{
  "duration": 12.4,
  "alignment": "provider-timestamps",
  "cues": [
    {"start": 0.4, "end": 3.1, "text": "两枚公平的骰子，"},
    {"start": 3.2, "end": 6.8, "text": "为什么七比十二更容易出现？"}
  ]
}
```

`start` 与 `end` 均为当前分镜内的秒数。导出整片时加上分镜的绝对开始时间。

- 服务商若提供时间戳，直接使用并校验先后次序与音频时长。
- 普通语音生成接口不一定返回词级时间戳。需要另外调用对齐服务，或按句分别合成后测量真实时长。
- 仅按字数估计的字幕应标为“预计时序”，不能冒充完成的语音对齐。
- 用户修改某个分镜时，只使该分镜的配音和字幕缓存失效；若音频实际时长改变，再重算后续分镜起点。
- 普通字幕默认最多两行，支持大小、位置和开关；准确数字、公式通过代码叠加。

浏览器 `speechSynthesis` 可作为临时试听，但通常不能可靠地作为离线导出的音轨来源。应明确区分“浏览器试听”与“可导出配音”。

## 背景音乐与混音

第一版建议允许用户上传 MP3、WAV、M4A 或浏览器可解码的音频，在本地处理；网站不自动下载参考视频的音乐。用户可以选择开始位置、音量、淡入淡出和循环。

导出时将旁白、BGM、动作音效接入统一的 Web Audio 混音图：

1. 校验音频能够解码并计算实际时长。
2. 根据分镜时间线裁剪或平滑循环 BGM，跨接处做短交叉淡化。
3. 按真实旁白的有声区间降低 BGM，避免用整镜静音或突变音量。
4. 预览与导出共用一套音量参数；字幕开关不影响旁白。
5. 母线预留峰值余量，避免多个音轨叠加削顶。

原始上传文件和最终混音文件的存储方式应分别说明。本地模式无需把用户音乐上传到模型服务；云端渲染模式才在用户主动导出时传输必需资产。

## 当前验证边界

环境未配置任何 TTS 模型密钥。一次临时 Edge TTS 连接测试在下载前因代理证书信任问题失败，没有生成音频；没有关闭 TLS 校验或绕过代理。根据用户随后提出的“先不生成视频，先做网站及调用 API 接口”要求，已停止进一步配音测试和音乐合成。
