# 见知 · Vibe Studio

一个可逐镜预览、修改和导出的知识视频网站。用户自行配置模型 API 后生成内容。本次交付不包含预生成视频，也没有调用付费模型。

## 在网站使用

1. 首页直接打开玻璃质感的创作工作台（`/` 与 `/studio.html`）。右上角可切换日间/夜间，并选择18/20/22px界面字号，偏好保存在本机；不会改变视频内容或视频风格。在「模型接口」分别选择文本、视觉返修、配音、视频的供应商、API Base URL、模型 ID 和 API Key。保留 DeepSeek Flash / MiniMax 默认预设，也支持 OpenAI 兼容、Anthropic Messages、Gemini 原生协议与自定义公开 HTTPS 接口。视觉模型可沿用文本配置，也可单独设置。URL与模型保存在本机，密钥刷新后清除。
2. 输入主题，选择时长、画幅、风格和制作方式，点击「生成分镜与代码画面」。第一阶段编排分镜；第二阶段按已接入的 [vibe-knowledge-film](https://github.com/HeyChengC/vibe-knowledge-film) 为每镜现写 JavaScript 动画代码，实际渲染三个时刻，再默认进行两轮看图返修。网站不再把少数固定图形替换文字后当作成片。
3. 分镜解析兼容包装层、镜头数组、中英文常见字段及时间范围，不再只接受单一字段格式。格式仍不完整时最多追加1次明确显示的整理请求；失败可下载已脱敏的返回内容，不自动循环重试。
4. 新建项目从第1镜开始严格按编号依次生成，不再优先复杂镜头。已有分镜在时间线的「按范围生成代码画面」选择未完成/全部/当前/自定义起止范围，默认保留已完成画面；取消勾选后可重做范围内已完成的画面。每完成一镜即可预览。进度显示真实阶段、已处理数、成功镜头数、失败和用时；等待模型时不伪造百分比。取消会保留已完成镜头，失败镜头可单独重试。语义修改会重绘当前镜头，其他镜头不重做。
5. 配音与 AI 视频镜头分别按需调用，旁白可只重做选中镜头或补齐缺失部分。AI/混合模式可明确选择一批镜头交给 H3，逐镜查询真实任务状态；代码预览不冒充 AI 视频。H3 每次支持 4–15 秒短片。
6. 默认使用用户提供视频中提取的 We Never（Vibe知识大赏），保留原速，已去掉尾部静音和抖音片尾。可切换为自己上传的配乐或原创氛围音乐；字幕、配音、配乐均可切换。
7. 在最新版桌面 Chrome / Edge 导出。支持 AVC 编码时为 MP4，其他支持的编码环境回退 WebM；浏览器不支持编码时会提示。未完成的绘图不会静默替换成通用模板后导出。没有配音素材时，不会凭空生成旁白。

常见预设：15、30、45、60、90、120、180、300 秒；9:16、16:9、1:1、4:5、3:4、4:3、21:9；黑金叙事、纸上实验、霓虹科技、工程蓝图、杂志信息图、宇宙深空、柔彩手绘、极简白。7 种画幅均用于实际预览与导出。H3 的 4:5 视频素材会由其原生支持的 3:4 裁切，界面会在提交前说明。

独立玻璃立方体参考页保留在 `/index.html`，单文件可通过 `/index.html?download=1` 下载；下载版本的工作台入口指向当前已部署网站。

初始画面是可交互示意，不代表已经调用模型或生成成片。配音的收费和视频任务收费由对应服务商计算。连接测试尽量使用非生成请求，不表示余额、地区或具体模型权限全部通过。停止等待不会保证取消服务商已经提交的任务。

## 密钥与保存

密钥只保存在当前页面内存，并通过同源 HTTPS API 代理转发给指定服务商；服务端不保存密钥，不写入项目、源码、日志或浏览器持久存储。刷新页面后需重新填写。项目 JSON 保存文字、参数、分镜与偏好，不保存 API Key 或二进制音视频；请另外下载重要生成素材。

本站已按所有者要求设为公开，任何拥有链接的人都可访问。每位使用者填写自己的 Key，网站没有共享密钥；其他访问者不会得到你的 Key、分镜或本机保存的项目。请求代理限制服务商域名，详见 [API 接口说明](docs/API.md)。

## 本地开发与部署

需要 Node.js 20+。运行时依赖为浏览器媒体封装库 Mediabunny 与动画语法解析器 Acorn；开发依赖包含 esbuild 和用于静帧测试的 @napi-rs/canvas。

```sh
npm ci
npm run check
npm test
npm run build
```

独立参考页 `dist/index.html` 按用户规格使用内联 CSS / JS、Three.js r169 CDN、Google Poppins 和指定远程 GLB，不依赖构建或本地素材；视频编辑器位于 `dist/studio.html`。

构建产物 `dist/server/index.js` 是 Cloudflare Worker ES Module，内含网页资源与 `/api/*` 接口。项目按 Sites 托管约定保存 `.openai/hosting.json`，也可将同一 Worker 部署到兼容环境。本地直接打开 HTML 只能查看前端；API 需要 Worker 后端。建议使用 Wrangler 等 Worker 开发环境运行后端。

## 实现与验证边界

- 新创作使用上游 `VK` 引擎和每镜独立 JavaScript 函数；代码只在无同源权限的 iframe 内的可终止 Worker 执行，不在应用主页面执行。语法检查、CSP与运行隔离共同限制代码。旧 JSON composition 仅用于项目兼容与内置示意。详见 [实际 skill 接入](docs/VIBE_FILM.md)。
- 忽略标签文字后比较绘图结构与运动指纹，拒绝完全相同的画面仅换标题。允许对象母题延续，但数学数据、几何或推演状态应真实改变。质量校验是有界检查，不等于已人工验证每次模型创作。
- 默认每镜1次代码生成加2次视觉返修请求（可选0/1轮），费用由所选文本与视觉模型服务计费；代码执行错误最多追加1次公开提示的文本模型修复；仍失败时按界面所选策略继续下一镜或暂停，保留失败源代码和诊断；鉴权、限流、网络和服务配置错误始终暂停。画面就绪、配音、AI 镜头和视频导出分别展示真实状态。
- 保留源项目、字幕与每镜版本，有效降低局部修改的重复生成成本。
- 当前通过请求模拟验证 API 协议、参数校验、密钥脱敏和错误处理，并通过 Node Canvas 运行上游引擎与网页 Worker 桥接器检查动画；未使用真实用户密钥调用服务。
- 本环境没有可用的共享浏览器控制工具，网页浏览器交互和浏览器视频编码尚待实际设备验证；本轮未生成音视频。

详见 [开源记录](docs/OPEN_SOURCE.md)、[知识事实](docs/FACTS.md)、[参考画面分析](docs/REFERENCE_STYLE.md)、[音频方案](docs/audio.md) 与 [偏好 skill 模板](docs/skill-template.md)。用户参考视频及抽帧没有放入公开站点或源码包。vibe-knowledge-film 引擎按 MIT 原样分发，Acorn 按 MIT 分发，字体为 SIL OFL 1.1 的 Noto CJK 子集。Mediabunny 按 MPL-2.0 原样分发，对应许可和源代码入口在网站「开源许可」页面提供。

## 本轮调试与工作流适配

- `visual.values` 只保留明确有限数字；“数万亿次”等数量措辞放入 `valueNotes`，不强转、不补0、不猜精确值。整个混合序列一起保留，避免标签错位。文字数量不会阻断分镜，也不会触发不必要的付费格式整理。
- “恢复已下载的分镜”可读入含`draft`的返回诊断JSON，通过`/api/script/restore`恢复原有脚本。恢复过程不调用模型、不需要API Key，画面制作单独点击开始。
- 参考用户上传的H3提示词skill，增加可选的“按H3工作流优化提示词”，只在点击时调用一次文本模型，返回主体动作时间轴、声景、配乐三个字段；视频任务另行提交。
- 参考通用版/Opus版知识工作流的事实、模拟、连续物件和静帧检查方法，未整体迁移Remotion工程，未分发用户工作流压缩包、PDF或样片。原工作流横屏/无音轨限制按用户的网站需求调整。
- 完整源码、依赖锁文件、运行库与许可证同步至 [one-word-vibefilm](https://github.com/KImlee107/one-word-vibefilm)。

## v0.6.0：绘图失败与工作台改版

原提示词把`ss`、`lerp`等短名称列在数学函数说明里，但执行器只传入`VK`，导致模型生成的合法短调用在绘图时抛出`ReferenceError`。现统一运行接口：支持`VK.ss`和`ss`等文档别名；本地同名变量可正常遮蔽。静态作用域检查提前识别其它未声明名称，生成前还会执行一次无模型费用的本地绘图探针。

每镜代码在执行前保存，错误包含检查/绘图/静帧阶段；最多追加一次针对原代码的修复请求，保留来源及用量。继续已有分镜时优先验证保留的最新失败代码，避免重新编排整片。模型鉴权、限流、环境和取消错误不会触发代码修复。

工作台采用玻璃卡片、冷色折光与立方体标识；重做昼夜配色及字体层级，设置栏独立滚动，预览区按画幅约束尺寸，消除长侧栏撑大的空白。原单文件WebGL示例独立保留。

## v0.6.1：顺序与范围

移除原来的“复杂镜头优先”调度，所有代码画面入口共用严格串行队列；输入编号会去重并升序执行，上一镜完成或失败后才开始下一镜。时间线增加已存在分镜的范围选择，起止编号为1起算、包含两端，非法/空/倒置范围在模型请求前被拒绝。新建脚本默认从第1镜顺序制作整片；范围控件只对现有脚本制作画面，不重新调用分镜接口。

单镜错误默认记录后继续下一镜，也可选“暂停后续镜头”；鉴权、额度/限流、网络、运行环境和服务配置错误始终暂停。生成进度区列出项目内每个失败镜头的原因，点击进入对应镜头查看代码诊断。失败不计入成功数；完成所选范围不会把范围外未完成的镜头标成完成。取消只影响尚未完成的请求，已完成成果保留。

## v0.9.0：We Never 默认配乐与音乐卡点分镜

默认音轨来自用户本轮提供的视频，AAC原流提取，去掉静音及抖音片尾，长184.783秒，未变速、未合成替代旋律。音频包含在源码与GitHub中；源视频不发布。该录音不属于本项目代码许可证，见 `dist/music/NOTICE.txt`。

实测主脉冲约112.8 BPM。旧低频起音检测对这首歌置信度不足，因此对实际解码音频执行离线频谱起音分析、自相关与相位拟合；分析评分0.779、细分拍相位一致性0.983、对齐残差均值6.7ms。BPM仍是估计，半速/倍速口径也可能成立；切换计划使用实际检测的起音位置，不把BPM直接等同于精确小节线。

- 网页默认启用“更多分镜，切换尽量跟随音乐拍点”。目标镜头数：15秒4镜、30秒7镜、45秒10镜、60秒13镜、90秒20镜、120秒27镜、180秒40镜、300秒48镜。模型返回数量可以有合理差异；过少的镜头会请求一次明确显示的整理，不复制场景凑数量。
- 先根据音轨拍点与实测能量安排切点，再让模型按各镜时间写简短讲解；返回实际镜头数后重新计算对应卡点时长，随后才逐镜绘制。每镜一般保留约4–7秒，一拍一切不会作为默认策略，复杂推导保留阅读时间。
- “查看拍点与切换计划”提供真实波形概览、切点时间表与是否匹配拍点。计划本身不调用模型；点击生成才会请求。镜头更多意味着调用更多，可先做前2镜样片。
- 新动画拿到当前镜内实际拍点，`fr.cue(比例)`可将数字出现、对象重组等关键事件轻度对齐到邻近拍点。固定输出总时长保持不变。
- 播放、导出与卡点计划使用相同循环边界：超过主体段落时循环，成片末尾自动淡出；预览与最终导出共用混音路径。更换配乐会改变新生成的卡点计划，已有旧画面不会被静默重分镜或改变其媒体时长。

离线重现：ffmpeg解码成8kHz单声道f32 PCM，再运行 `python tools/analyze-default-music.py input.f32 dist/music/we-never-profile.js`；可选Python依赖见 `tools/requirements-audio.txt`。网页运行不依赖Python、ffmpeg或第三方音乐服务。

## v0.8.0：单镜重设计、样片流程与数学排版

- 新增生成流程：全部画面、只做前2镜样片、仅生成分镜。样片以严格编号顺序制作，其余镜头等待用户按范围继续，不会自动提交。
- 原稿仍失败后可选保留文案重设计一次、简化文案后重设计一次，或仅留诊断。重设计最多额外1次文本请求；改写后重做最多额外2次。新稿只做本地验收，不重新启动付费视觉轮次或修复循环。服务商余额、鉴权、网络等共享错误直接停止。
- 右侧提供“保留文案，重新设计画面”和“简化本镜文案并重做”。前者丢弃待恢复的失败草稿，重新请求当前镜的独立设计；后者先改写，再绘图。数字与公式有保留校验，完整科学正确性仍需人工核实。文案变化只使当前镜原有配音/视频失效，其他镜头保留；修改可撤销。
- 最近可渲染稿的三个真实关键帧在右侧显示，可点击放大，含本地检查结果。静帧只保留在本页内存，不写入项目或上传GitHub；导入旧项目后可使用“检查现有画面”重新抽帧，无需API。
- 修复生成指引中变换坐标不清的问题：`fr.g({at})`内部使用局部坐标；新增`fr.pivot`支持围绕指定点缩放绝对坐标。新增按文字宽度排列的`fr.fraction`、`fr.equation`，以及正面点阵准确且有明暗对比的`fr.die`、单一外框的`fr.probabilityBar`。这些是基础绘图工具，每镜构图、机制和动画仍由模型重新设计，不是固定场景模板。
- 视觉模型可明确批准已经清楚的原稿，仅在本地测量报告通过且有实际帧与反馈时保留原程序；仍需在客户端重新检查，不再强迫无意义改动。已有重叠等问题不能以批准绕过。

两个用户资料包只作为设计参考，提炼了样片预览、真实关键帧、分层表达与有上限的返修；未复制安装其中全部14个Skill，也没有执行资料包脚本或引入未经核对许可的第三方代码。没有新增模型依赖或开发时的付费生成。
